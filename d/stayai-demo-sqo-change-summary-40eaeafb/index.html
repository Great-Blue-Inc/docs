02

What changed

Flow v12 active in sandbox

One flow element changed its filter, one assignment carries the amount, three settings records replaced one.

The lookup, before and after flow builder

filter: record name = Default

Before (v11). The lookup reads the single settings record named Default. Every deal got the same amount, whatever the segment. The line outlined in red is the filter.

filter: segment label = account segment

After (v12). The same lookup now matches Segment Label to the account's segment. The record name filter is gone. Same element, same position, one filter changed.

The amount assignment flow builder

amount from the matched segment record

After (v12). The assignment copies the matched record's Pre-Qual Amount into the variable the Opportunity create uses. When no record matched, the variable stays empty and no Amount is written. The decision above it is labelled Segment Amount Found and No Segment Amount.

Settings and the rule low level

Custom Metadata recordSegment LabelPre-Qual Amount
Opportunity_Default.SMBSMB5,000

Opportunity_Default.DefaultDeleted. Replaced by the three above.
Opportunity.Amount_Required_To_Leave_Pre_Qual
Validation rule. Fires when the stage changes from Pre Qualification to anything except Closed Lost, Disqualified or Nurture, and the amount is blank, zero, or equal to the account segment's starting amount from the metadata (a CASE over the three records).
Opportunity_Default__mdt.Segment_Label__c
Text. Matches the picklist text of Account Segment, hyphen included.
Opportunity_Default__mdt.Pre_Qual_Amount__c
Number. The starting amount written on a new Chili Piper deal.
Finding during the build

Account Segment cannot be set by hand unless the manual override flag is true. An insert with a blank segment succeeds with no error, and the deal then gets no amount. Expected, and documented so nobody reads it as a flow fault.
