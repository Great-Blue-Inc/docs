Pricing Engine Map

How a price is built, where every piece of logic lives, and the order to read it in. One page to hold before walking any code.

The one-paragraph versionWhat this system is

The app collects a job's inputs — garment, decoration, quantities, margin target. One small class picks the right pricing mode for the sheet. That mode walks the price steps in order, exactly the way the pricing spreadsheet does, reading two kinds of data as it goes: the rate card (every dollar figure, stored as versioned records) and the price rules (admin-managed adjustments). The result comes back with every step itemized, and the app draws that same walk on screen as “How this price is built.” Code decides how to calculate; data decides the numbers. Changing a price never means changing code.

Class by classWhere the logic lives

Class Its one job Logic Read it when…
CostSheetCalculator Entry point. Picks the pricing mode, owns the margin → sell math every mode shares. 32 lines …you want to see where every calculation begins.
ICostSheetPricingMode The contract each mode signs: one method, price a request. 3 …you wonder how three modes stay interchangeable.
FullPackagePricingMode The main walk — steps 1 through 8.5 for in-house jobs. The only class that does every step. 261 …you want the full story. Read second, top to bottom.
ContractPricingMode Customer supplies the goods; prices decoration from the contract rate card. 84 …after the main walk — it’s the same shape, shorter.
ThirdPartyPricingMode Outside vendor makes the item; finished cost + freight & duty, then margin. 48 …same time as Contract. Shortest of the three.
PriceRuleEngine Matches active price rules to the job and applies them — cost side, then sell side. Keeps the fired-rule audit trail. 136 …you want to know exactly what a rule can and cannot touch.
CostSheetRateLookup The only reader of the rate card. Every dollar figure in every step comes through here. 105 …you ask “where did that number come from?” The answer is always: here, from a rate record.

Around the engine: CostSheetApi (the doorway), CostSheetLifecycleService (save, load, quote, clone to production), CostSheetActualsService (recomputes at actual order quantities), CostSheetQuoteRenderService + CostSheetPdfController (customer-facing output), and two data shapes — CostSheetCalcRequest in, CostSheetCalcResult out. The engine itself is pure math: no queries, no saves, fully testable.

Code vs dataWhere every number comes from

Data — an admin changes these, no deployment

  • Rate card — every rate, tier and fee, as versioned records. A quoted sheet keeps the version it was quoted under, forever.
  • Price rules — “name contains Cotton → +10% sell.” Created in the app with a preview of the exact price change before switching on. Off is one click. Zero rules = pricing is exactly the spreadsheet’s.

Code — changes go through review and tests

  • The step order and what each step means.
  • The formulas — screens from colors, setup + run rates, margin, rounding.
  • Every formula is proven against hand-worked figures from the pricing spreadsheet itself; a side-by-side run of the same job lands on identical numbers, to the cent.

Honest edges, on purpose: embroidery and DTF pricing await their rate tables, and the licensing royalty formula isn’t reproduced yet. Until then the engine answers “outside rate card” for those paths — it never guesses a price it can’t stand behind.
