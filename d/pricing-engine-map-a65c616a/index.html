Pricing Engine Map

How a price is built, where every piece of logic lives, and the order to read it in. One page to hold before walking any code.

The one-paragraph versionWhat this system is

The app collects a job's inputs — garment, decoration, quantities, margin target. One small class picks the right pricing mode for the sheet. That mode walks the price steps in order, exactly the way the pricing spreadsheet does, reading two kinds of data as it goes: the rate card (every dollar figure, stored as versioned records) and the price rules (admin-managed adjustments). The result comes back with every step itemized, and the app draws that same walk on screen as “How this price is built.” Code decides how to calculate; data decides the numbers. Changing a price never means changing code.

Class by classWhere the logic lives

Class Its one job Logic Read it when…
CostSheetCalculator Entry point. Picks the pricing mode, owns the margin → sell math every mode shares. 32 lines …you want to see where every calculation begins.
ICostSheetPricingMode The contract each mode signs: one method, price a request. 3 …you wonder how three modes stay interchangeable.
FullPackagePricingMode The main walk — steps 1 through 8.5 for in-house jobs. The only class that does every step. 261 …you want the full story. Read second, top to bottom.
ContractPricingMode Customer supplies the goods; prices decoration from the contract rate card. 84 …after the main walk — it’s the same shape, shorter.
ThirdPartyPricingMode Outside vendor makes the item; finished cost + freight & duty, then margin. 48 …same time as Contract. Shortest of the three.
PriceRuleEngine Matches active price rules to the job and applies them — cost side, then sell side. Keeps the fired-rule audit trail. 136 …you want to know exactly what a rule can and cannot touch.
CostSheetRateLookup The only reader of the rate card. Every dollar figure in every step comes through here. 105 …you ask “where did that number come from?” The answer is always: here, from a rate record.

Around the engine: CostSheetApi (the doorway), CostSheetLifecycleService (save, load, quote, clone to production), CostSheetActualsService (recomputes at actual order quantities), CostSheetQuoteRenderService + CostSheetPdfController (customer-facing output), and two data shapes — CostSheetCalcRequest in, CostSheetCalcResult out. The engine itself is pure math: no queries, no saves, fully testable.

Code vs dataWhere every number comes from

Data — an admin changes these, no deployment

  • Rate card — every rate, tier and fee, as versioned records. A quoted sheet keeps the version it was quoted under, forever.
  • Price rules — “name contains Cotton → +10% sell.” Created in the app with a preview of the exact price change before switching on. Off is one click. Zero rules = pricing is exactly the spreadsheet’s.

Code — changes go through review and tests

  • The step order and what each step means.
  • The formulas — screens from colors, setup + run rates, margin, rounding.
  • Every formula is proven against hand-worked figures from the pricing spreadsheet itself; a side-by-side run of the same job lands on identical numbers, to the cent.

Honest edges, on purpose: embroidery and DTF pricing await their rate tables, and the licensing royalty formula isn’t reproduced yet. Until then the engine answers “outside rate card” for those paths — it never guesses a price it can’t stand behind.

The build walkBuilding a cost sheet, start to finish

Every stage of the builder, every field on it, and the point where you move on. Turn on the switch below to see which class answers each stage.

OPENGetting into the builder

The builder is always scoped to one development item. It is opened from that record, never on its own.

  1. Open the Development Item.
  2. Find the Cost sheets & quotes card in the left column. It lists the sheets already on this item, with the newest marked Latest.
  3. Click Open cost sheet builder.
  4. Click New cost sheet. The sheet is created and the item's details are copied onto it.

CostSheetApi is the doorway — it takes the request and routes it, holding no pricing logic of its own. Creating the sheet runs CostSheetService.createFromDevelopmentItem, which writes the header record and copies the snapshot fields. Where the Art Request and the development item both carry a value, the Art Request wins and the item is the fallback.

STEP 1Header & mode

Three blocks: what was copied in, how this sheet should be priced, and the figures you enter yourself.

Item Details — read-only. A snapshot taken when the sheet was made, so a quote sent months ago still says what it said then. To change any of it, fix the source record and make a new sheet.

Design ID
Art Request → Design ID. Falls back to the development item.
Padneck ID
The printed neck label. Art Request → Padneck ID, falling back to the development item's own Padneck field.
Customer / Customer ID
Account → Customer ID, from the account on the development item.
Buyer name
The buying contact for this sheet.
Blank style #
Art Request → Blank Style Number. Empty when no Art Request is linked.
Blank description
Art Request → Blank Description.
Blank color
Art Request → Blank Color.
Comp
Art Request → Comp URL. The artwork thumbnail beside the block.
Garment type
Chosen here, not copied. It decides which rows of the rate card the calculator reads, so it changes the numbers.

Pricing mode — the one choice that changes everything below it.

Full Package
The shop buys the blank, decorates it and packs it. Walks all eight steps.
Contract
The customer supplies the goods and the shop only decorates them. Priced from a fixed rate card.
Third Party
An outside vendor makes the finished item and the shop adds margin.

Quote details — what you enter.

Option description
A label telling this option apart from the others on the same item. Optional, and it never touches a price.
MOQ
Minimum order quantity. Use 144. Quantity is what price breaks are read on, so this drives the whole cost side.
Margin target %
The margin to price at. Use 35. Applied at the end and it never changes a cost.
Blank cost (primary size)
What one garment costs before anything is done to it. Use 2.88. This is price step 1.
Blank vendor
Who supplies the blank. Recorded on the sheet, not priced.
Freight per piece
Inbound freight, per piece, as entered. Leave empty unless the job carries it — empty contributes zero rather than blocking the price.
Licensing number
Development item → Licensing Number. Only for licensed designs. The Art Request has no equivalent, so this one has no fallback.

Third Party adds two fields no other mode has: Third-party finished cost (per piece) and Third-party freight/duty (per piece).

Click Continue, bottom right, to reach Decoration. Every stage has Continue and Back there, and the five stage names across the top jump straight to any stage.

Nothing prices yet. CostSheetLifecycleService loads the sheet and saves it, replacing the child rows each time because the builder returns the whole form. Pricing mode picks which class does the work later: FullPackagePricingMode, ContractPricingMode or ThirdPartyPricingMode, all three behind the ICostSheetPricingMode interface.

STEP 2Decoration

What is put on the garment. This is price step 2.

  1. Add a decoration line and choose its type: Screen Print, Embroidery, DS, DTF or Applied Element.
  2. Set the Location — front, front pocket, back, spine, sleeve, left chest, back neck, or a custom placement.
  3. For a screen print, set Colors to 3. The colour count sets the number of screens, which drives the setup charge and the run cost.
Name drops
Personalised names on the print, priced at the print hourly rate.
Element type
Applied Element only: patch, diecut transfer, hem tag, bow or other.
Application method
Applied Element only: heat pressed or sewn.
Manual cost / Apply minutes
A per-piece cost entered by hand, and the labour minutes to attach it.
Treatments
Under More options. A treatment, how many Hits it takes, and a Price override when the standard rate does not apply. Foil also asks for a height. This is price step 3.

Click Continue.

FullPackagePricingMode owns this step, and every figure it uses comes from CostSheetRateLookup — by name, by piece count for a price break, or by piece count and a second measure together for the screen-print grid.

STEP 3Tiers & sizes

The stage people miss. Until a quantity tier exists there is nothing to price, and the panel says so instead of showing a number.

  1. Add a Quantity tier at 144. Each tier shows its Suggested sell price, a Quoted price you can confirm, and a Margin est.
  2. Add Per-size blank costs if larger sizes cost more — a size and its upcharge.
  3. Open How this price is built.
Check the walk. Blank $2.88, then decoration, treatments, packing, freight and other, then a total cost, then margin, then the suggested sell. Every row is one price step, in order, and nothing about how a number was reached is hidden.

Add a second tier at a higher quantity and the per-piece decoration drops, because the setup charge spreads over more pieces. That is the price break working. Click Continue.

Each tier is priced by the mode class, then CostSheetCalculator.suggestedSell() turns the total cost into a price: cost divided by one minus the margin, rounded up to the rate set's own increment. The panel is the same itemised result the API returns, drawn for the user.

STEP 4Samples, packing & other

The rest of the cost stack — price steps 4 through 6.

Sample allocation
Units set aside rather than sold: a recipient (licensor, buyer, display or other), a size and a quantity.
Packing
The standard packing bundle, plus any add-ons charged per piece. Fold, box, ticket. This is price step 4.
Other cost factors
Anything left: rework, royalty, licensing or misc. Each carries an Amount, a Per piece switch deciding whether it applies to every unit or the order once, and an Internal only switch that keeps it off customer-facing output. This is price step 6.

Leave any of these empty and it contributes zero. Click Continue.

Still FullPackagePricingMode, reading its figures through CostSheetRateLookup. An internal-only cost is carried in the total but withheld from the rendered quote.

STEP 5Quote summary

Name it, check it, and decide what happens to it.

  1. Set the Cost sheet name and check the summary figures.
  2. Quote freezes the sheet. A save is refused after this, on purpose — a quoted price cannot move underneath the customer.
  3. Accept quote records that the customer took it.
  4. Clone to production is the way forward from a frozen sheet. The production copy reopens only the fields filled in at order time; everything cloned stays as it was.
  5. View PDF renders the quote as the customer sees it.

CostSheetLifecycleService owns all of it — the freeze, the refusal to save afterwards, the accept and the clone. CostSheetQuoteRenderService builds the rendered quote, and CostSheetActualsService handles the recompute once real figures come back from the floor.

RULESPrice rules

Adjustments an administrator manages as data. No deployment, and no code changes.

  1. Open the Price rules panel and click Create rule.
  2. Choose what it matches on — garment type, decoration type, customer or program, or product name — using Equals or Contains. Capital letters do not matter.
  3. Choose what it does: Cost Uplift Percent or Cost Adder Per Piece.
  4. Click Preview on this sheet before saving. It prices the sheet twice and shows you before and after, so nothing is committed blind.
  5. Activate the rule, then reopen the price panel.
Three rows appear where there was one: the price before rules, the rule itself and what it added, and the final price. Deactivate the rule and the price returns to exactly what it was.

Two rules given the same run order stop pricing with a clear error rather than guessing which should go first. Deactivating is the off switch — nothing is deleted, and the run-order slot is freed.

PriceRuleEngine checks each active rule against the sheet and applies the ones that fit, in run order. Cost-side rules adjust cost; sell-side rules adjust the price. Every mode calls the same class, so a rule behaves identically everywhere. CostSheetPriceRuleService is the panel's own surface — list, create, update, activate, deactivate and the preview.

MODESThe other two ways to price

Same builder, shorter walks.

Contract. Set the MOQ and margin target, add one screen-print line in two colours, and add a tier. The price comes from a grid: find the row for the piece count, then the column for the number of colours. That one cell is the price. One line in the panel is the whole answer, because contract work skips the blank, the treatments and the packing completely. A cell printed on the card with no price in it is the card's own "call us" row, so the sheet asks for a special quote.

Third Party. Enter what one finished piece costs and the freight and duty on it, then add a tier. Four lines and it is done. Leave the finished cost empty and the sheet says exactly what is missing — it never shows a zero-dollar price somebody could quote by mistake.

ContractPricingMode and ThirdPartyPricingMode. Both implement the same interface as Full Package and both call PriceRuleEngine, which is why a rule written once applies wherever it matches.

The line that ties all of it together: code decides how to calculate, data decides the numbers. Changing a price never means changing code.
