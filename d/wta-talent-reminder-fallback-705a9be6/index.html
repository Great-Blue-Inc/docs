Contract reminders now reach a typed email address

The nightly reminder flow could only send to a contact record. A contract sent to a typed address errored every night and the recipient got nothing. This page shows the exact elements that changed, before and after, and where the change stands.

Problem and fix

Reported on Doc-29571. The agent sent the contract to a typed address instead of a contact.

Root cause high level

Concord stores the send-to address in one of two places. When the agent picks a contact, the contact lookup is filled. When the agent types an address, only the Email To field is filled and the contact lookup stays empty. All seven reminder sends in the flow use a Salesforce email template, and a template send requires a contact record. With no contact the send fails with Recipient ID is required when using templates, the flow stops, and no reminder goes out.

The fix high level

RequirementSolution
Reminders must work when the contract was sent to a typed addressA check before each of the seven sends. Contact set: the existing template send runs unchanged. No contact: a new send delivers the reminder to the Email To address on the eSign record.
Same wording the recipient gets todayThe three reminder templates (client, talent, second signer) were copied word for word into the flow for the no-contact path. No new copy.
A sender when the opportunity has no agency addressProposed: fall back to no-reply@washingtontalent.com, the address the invoice reminders already use. Decision open.

What changed

Flow Builder captures. Left or top is production version 17. Right or bottom is the sandbox candidate, version 27.

The branch low level

The send low level

Repeated seven times

The same guard and fallback pair was added in front of every reminder send: four client reminders, one talent reminder, two second-signer reminders. Each fallback carries the wording of the template it replaces. Nothing else in the flow was touched.

Verification low level

  • Before, September 1. Debug run of the active sandbox version on the test record with no contact. Result: the exact production error at the talent reminder send.
  • After, September 1 and 2. Debug run of the candidate on the same record. The guard took the no-contact path, the fallback ran, and the reminder arrived at the test inbox with the talent wording and merge fields filled.
  • Sender fallback, September 2. Same record with its opportunity unlinked, the shape of Doc-29571. The reminder arrived from no-reply@washingtontalent.com.
Deploy state

Production runs version 17 and has not been changed. The candidate is sandbox version 27, saved as an inactive draft. Deploying it creates version 18 in production and activates it. Rollback is one step: reactivate version 17. The no-reply sender default and the go-ahead to deploy are open decisions.
