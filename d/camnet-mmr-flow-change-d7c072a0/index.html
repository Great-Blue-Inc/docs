Live, verified

One requested condition change, plus the org-wide fault found while proving it.

02

What changed

Real Flow Builder captures, version-pinned. Before is the running production version. After is the deployed inactive draft. The same edits were verified byte-level against a fresh production retrieve before deploy.

Opportunity close flow: the product-name gate RTF_Opportunity_On_Update_After_Save_V2

matches MMR only, all-conditions

Before (v39, Active). The MMR Product? decision fires on one condition: product name equals MMR. A closed MSP plan without that line never sets the MMR flag. The area outlined in red is the entire gate.

OR + the three MSP plans

After (v40, Inactive). The same decision now reads Any Condition Is Met with four values: MMR, MSP Growth, MSP Elite, MSP Strategic. The identical edit was applied to the flow's second copy of this decision (MMR_Product_0).

Contract flows: the missing owner input RTF_Service_Contract_On_Update_After_Save

owner never passed

Before (v57, Active). The Create MMR Work Orders subflow call. varOwnerID, outlined in red, is Not Included. The subflow requires it and exits without creating anything when it is blank. This is the line that killed automatic MMR generation org-wide on 05-11.

owner wired in

After (v58, Inactive). The same panel with varOwnerID Included, mapped to Triggering ServiceContract > Owner ID. The contract create flow (RTF_Service_Contract_On_Create_After_Save, v17 to v18) received the identical five-line addition, so brand-new MSP contracts generate on creation again.

The subflow itself: two wrong wirings Subflow_Create_MMR_Work_Orders · v21 to v22

Activating the three flows above exposed one more fault. The subflow located its service contract through an input named recordId that no caller supplies, including the screen flow staff use by hand, and then wrote that same value into the work order's Opportunity lookup, where a contract id can never be valid. No caller could satisfy both. Two element-level corrections:

Get Triggering Service Contract, lookup filter:
  Id Equals {!recordId}            before: an input nothing passes
  Id Equals {!ServiceContractId}   after: the input every caller passes

Build WO In Memory, Opportunity field:
  Opportunity__c = {!recordId}     before: a contract id in an Opportunity lookup, faults the insert
  Opportunity__c = {!OppId}        after: the real opportunity input, null when absent
Verified live

With v22 active, one toggle of the East Mountain contract's generation flag produced its complete 53-work-order weekly schedule (MMR #1 through #53, owners set) through the product's own automation. Zero manual inserts.
